# Runtime Policy Catalog

> **Purpose:** What the research agent does at runtime when something goes wrong: exceptions, retries, degradation and failure paths.
> **Authoritative for:** runtime handling policies. Each policy traces to a requirement or invariant.
> **Maintained by:** owners of modules with exception, retry, degradation or failure handling write a module section (§2); §1 is integrated from those sections before SA Review. Modules without such handling add nothing.

| POL-001 | A researcher raises a non-token-limit exception other than `asyncio.CancelledError` (cancellation is POL-008) | `classify_task_error` after `asyncio.gather(..., return_exceptions=True)` collects the exception instead of raising it | Only that task ends `failed` with category `runtime` and `str(exc)` as the message; siblings keep their results; the phase continues and control returns to the supervisor | None in this delivery: a failed task is not retried automatically and not re-planned. | POL-002 | A researcher raises an error that `is_token_limit_exceeded(exc, research_model)` recognises | provider-specific token-limit patterns in `utils.is_token_limit_exceeded`, with the error string as fallback when the provider is unknown | Only that task ends `failed` with category `token_limit`; the research phase does not end, because a researcher's context limit says nothing about the supervisor's | Compression-side recovery belongs to REQ-005 (`context/`), not here. If compression still cannot fit, the task result is `token_limit` all the same | Same rule as POL-001 | REQ-002 C-003 / INV-002 S1 | `::test_token_limit_error_is_task_failure` |
| POL-003 | A supervisor turn holds more `ConductResearch` calls than `max_concurrent_research_units` | `len(specs) > max_concurrent` in `run_delegations`, enforced by an `asyncio.Semaphore` around each researcher call | All specs are launched at once and the semaphore lets at most `max_concurrent` run; the rest wait for a free slot and then run, so every delegation ends with a `TaskResult` and a slow task does not hold back the others. The baseline error string for overflow is no longer produced | No retry. The semaphore keeps peak concurrency at the configured limit, so rate-limit pressure is unchanged | `partial` only if some of the queued tasks still fail | REQ-002 C-004 / INV-006 | `::test_overflow_delegations_are_queued` |

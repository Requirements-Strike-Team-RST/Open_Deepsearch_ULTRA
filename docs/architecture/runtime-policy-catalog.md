# Runtime Policy Catalog

> **Purpose:** What the research agent does at runtime when something goes wrong: exceptions, retries, degradation and failure paths.
> **Authoritative for:** runtime handling policies. Each policy traces to a requirement or invariant.
> **Maintained by:** owners of modules with exception, retry, degradation or failure handling add rows to §1 for their module; rows are integrated and renumbered before SA Review.
> **Last updated:** 2026-11-17

## 1. Policies

All policies are *Proposed* until SA Review. A policy applies when the flag of its module is on (`structural-constraints.md` §8); search and evaluation have no flag. "Outcome effect" refers to the run outcome of REQ-004 (`complete`, `partial`, `failed`).

| Policy ID | Trigger | Detection | Behaviour | Retry / degradation | Outcome effect | Module | Source | Test |
|---|---|---|---|---|---|---|---|---|
| POL-001 | A researcher raises an exception that is not a token-limit error | `run_delegations` collects it with `gather(return_exceptions=True)` | Only that task ends `failed/runtime` with the error message; siblings keep their results; the loop continues | No automatic retry; the supervisor may delegate again | `partial` if other tasks found something, else `failed` | delivery | REQ-002 C-001, C-002 / INV-007 | `test_failure_propagation.py::test_child_exception_becomes_failed_result` |
| POL-002 | A researcher raises a token-limit error | `utils.is_token_limit_exceeded(exc, research_model)` | Only that task ends `failed/token_limit`; the research phase does not end | None | as POL-001 | delivery | REQ-002 C-003 / INV-007 | `test_failure_propagation.py::test_token_limit_error_is_task_failure` |
| POL-003 | A turn has more delegations than `max_concurrent_research_units` | A semaphore in `run_delegations` | Extra tasks wait for a free slot and then run | None | none by itself | delivery | REQ-002 C-004 / INV-007 | `test_failure_propagation.py::test_overflow_delegations_are_queued` |

## 2. Adding a Policy

Add one row to §1 with the next free `POL-NNN` number and fill every column. Name the policy's ID in the ADR's §6 and, if it enforces an invariant, in `invariants.md`.

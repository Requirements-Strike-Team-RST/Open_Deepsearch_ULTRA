**Integration boundaries and unresolved approvals**

- `N = max_researcher_iterations` counts successfully processed supervisor turns, starting from zero and incrementing only after the tool-turn has processed/joined. `N=1` permits the first delegation turn and then exits below threshold at the cap. At a supervisor entry already at `N`, the selector runs before another model request. The existing flag-off `research_iterations` counter is unchanged.
- The original `ConductResearch` remains the flag-off tool; the flag-on tool keeps the external tool name `ConductResearch`. Failed results retain required registered questions, explicit categories/reasons and evidence-derived spend. Delivery returns a result delta; the shared node boundary alone publishes state. Context owns trimming/classification/recovery, citations owns its canonical Sources instructions, and delivery owns queuing/join/failure isolation/outcome.
- Before implementation, readers must resolve the accepted-delegation diagnostic contract, flag-off/context-on failure boundary, native search compatibility restriction, unfinished-receipt recovery, and the overlapping context proposal to edit delivery's missing-summary consumer. No shared-reader approval or human gate is supplied by these policies.
- Reactive token-limit recovery is not a proactive input-budget measurement. The missing input/context-window token cap is retained as a course-compliance gap for the integrator, not described as an implemented runtime guard.

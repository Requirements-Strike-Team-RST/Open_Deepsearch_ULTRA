## 2. New actionable gaps (max 5)

**G1 — No delivery→orchestration adapter contract.** ADR-002 §5 defines only orchestration-side helpers. Delivery (dispatch, queue, isolate, join) must hand the node an ordered, per-call outcome that the node can map into `TaskResult` without knowing orchestration internals, and must state authority: the node *assigned* task ID, normalized questions and registered spec win over any child copy. The only anchor is the single sentence "Delivery returns each turn's ordered **plain list delta** via `update_payload["task_results"]`" (§6), while `§3.1` says a malformed raw intent yields a rejected diagnostic instead of a `TaskResult`. Which of the two forms (`{registered spec, outcome, starts}` vs `TaskResult | rejected`) the node receives is unspecified, and ORC-040 expects output that no case supplies.
*Smallest fix:* one table in ADR-002 §5 — `DispatchOutcome(call_id, spec, kind ∈ {result, rejected, not_started}, payload, asyncio.Task handle)` with the invariant "publish order = original call order, independent of completion order"; register one planned case (e.g. ORC-044) that is exactly scenario 1 under concurrency 1; add ORC-016's "one pending valid task" to ORC-042's input.

**G2 — `RunRecord` carries no per-question data; REQ-004 C-002/C-006 need it.** `TaskResult` has `must_answer` and `coverage` but no answered-question set, and `RunRecord` has only verdicts (ADR §5). To keep REQ-003 calculations single-source, delivery should take the unanswered questions from the codeset lists the node already builds for feedback (ADR §3.4 "return unresolved original questions in deterministic order"), not recompute coverage from floats. ORC-032 rejects inconsistent coverage but never checks the limitations content derived from it.
*Smallest fix:* one sentence in memory §5 (Approximate the `exit_detail`/`RunRecord` row): "unanswered required questions are emitted by the node in the `not_run`/`unanswered` reason lists and are the only source for delivery's limitations text"; extend ORC-032 or REQ-004 C-002 planned input.

**G3 — The state-carried adversarial path is unplanned.** ORC-023/ORC-024 pass a raw compression *string*; the researcher actually hands `ResearcherOutputState` a `task_result` plus `raw_notes`, without `compressed_research`. The baseline consumer (`:310`) defaults it to the placeholder string and ORC-024 assigns the consumer hunk to Alchemy (R-09), yet no case defines what the consumer does when `task_result` exists and the string is absent.
*Smallest fix:* extend ORC-023's inputs with `{task_result: failed/invalid_result, compressed_research: absent, raw_notes: placeholder text}` and one expected sentence: "exactly one result per call; placeholder/sidecar text appears in neither notes, summary nor ToolMessage."

**G4 — Pre-entry failure policy beyond "not_run".** When the supervisor entry finalizes at an already-reached cap (ADR §3.4), there is no turn to hold calls, but an earlier rejected intent or a conflicting replay whose **conflicting response was never emitted** has no stated producer. ORC-043/ORC-038 cover identical replay but not a first-time observation at entry.
*Smallest fix:* one sentence in ADR §3.1: at entry finalization every not-yet-answered rejected receipt emits its diagnostic response exactly once; add the corresponding boundary to ORC-043.

**G5 — Off/on boundary (declared pending, R-05/ORC-036).** Not a new contradiction, but delivery must not mask it by reading `task_results` when orchestration is off. Recorded as pending, not as a missing contract.
